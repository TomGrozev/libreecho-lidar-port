# Step 33 gap checks: kernel probe and binding gaps (KernelGaps)

Device: LibreEcho 0.2.24, kernel 6.18.64+ (`uname -a`, boot 2026-11-21 20:56),
`adb -s <DEVICE_IP_A>:5555`. All commands were read-only; nothing was written to the device.

Evidence in this directory:

- `dmesg-full.log`: complete `dmesg` of the current boot.
- `bindings.log`: every i2c client and every platform device without a bound driver.
- `sysfs-state.log`: `/sys/class/rtc`, `/sys/class/thermal`, top-level DT nodes, SPM registers,
  `waiting_for_supplier`, kernel config selections.

| RTC (`rtc_available=0`, `RTC persistence failed`) | no RTC hardware exists; board correctly reports none | `sysfs-state.log` (`/sys/class/rtc` absent, `CONFIG_RTC_CLASS is not set`, `CONFIG_MFD_MT6397 is not set`); top-level DT has no `rtc` node; no RTC on i2c0/1/2 (`bindings.log`); `libreecho-lidar.dts:103-107,633-637`; reference `mt8516-amazon-lidar.dts:10,392-394` | `timed` calls `ensure_rtc_node()` and, failing, sets `rtc_available=0` and `LIBREECHO_TIME_ERROR=RTC persistence failed` (`repos/LibreEcho-UI/src/adapter/timed.c:184-186,303-313`). There is no RTC to bind: MT8167 has no SoC RTC; the RTC lives in the MT6392 PMIC behind pwrap, this board has no PMIC (stock leaves pwrap disabled and gives it no child; our DTS copies that), and no external RTC chip is on any i2c bus. `CONFIG_RTC_CLASS` is also unset, so even a PMIC could not register one. Fix proposal (board reality, not a driver bind): treat Lidar as NTP-only. Make `timed` persist the last valid epoch to userdata and restore it at boot with a monotonic offset, and report `rtc_available:false` as the expected state (the API/UI already render that: `web/js/app.js:2006`). Enabling `CONFIG_RTC_CLASS`/`CONFIG_MFD_MT6397` alone would change nothing, since no RTC device exists. Offline wall-clock accuracy across a power loss is impossible on this board. Impact: after a power loss without a network the clock starts unset; timers/alarms that persist across reboot lose wall-clock accuracy (in-session timers verified working in step29). |

## Summary by user-visible impact

1. **Behavioural bug, easy fix**: TSL2540 never probes (missing `als_name` DT property). Affects
   `GET /api/v1/light` (501) and `/status.light_lux` (-1) only; no LibreEcho behaviour uses lux.
2. **No functional impact, worth fixing for boot time/power**: `mtk-power-controller` aborts on
   the unused GPU `MFG_ASYNC` domain (-110), costing ~1 s per boot and preventing unused-domain
   power-down. Mark the MFG domains `MTK_SCPD_KEEP_DEFAULT_OFF`, or disable `spm` in the board DT.
3. **Hardware reality, not a bind bug**: no RTC exists on this board (no PMIC, no i2c RTC,
   `CONFIG_RTC_CLASS` unset). `timed`'s `rtc_available=0` is correct; persistence needs a
   software epoch store in userdata, not a driver.
4. **Telemetry gaps**: `ti,tmp112` unbound (one thermistor), and no thermal zones at all, so
   `/status.temperature_c` is always 0.

Nothing here required a device write, so nothing needs owner approval. The proposed changes are
DTS/config or `timed` source changes for a later round.
